# 台股 AI 選股模型系統

用真實的台股歷史資料訓練機器學習模型，每個交易日收盤後自動選出十檔股票、自動判斷出場，並把每一次的績效攤開來給人檢視。**重點不是幫你賺錢，是讓「這個模型到底有沒有用」這件事變得可以量、可以看、可以推翻。**

> ⚠️ **本專案僅供學習與研究，不是投資建議，也不連接任何券商。**模型目前量到的訊號很弱（見下方「目前的成效」），拿去實際操作只會賠錢。

## 這是什麼

- **不是**交易模擬器，也沒有虛擬資金。系統只記錄每一筆持有的**淨損益率百分比**（已扣手續費 0.1425% 與證交稅 0.3%），因為模型的好壞跟投入多少錢無關，而假的虛擬資金只會讓人誤以為那是真實績效。
- 只做 **TWSE 上市**股票，不做上櫃與興櫃。
- 每次訓練產生一個**不可變的模型版本**。版本可以封存（停止每日選股但保留歷史），也可以刪除。
- 一般訪客**不需要登入**就能瀏覽所有模型的參數、指標、圖表與持有部位。只有訓練與管理需要管理員登入。

## 模型怎麼運作

**雙任務**：同一組特徵同時訓練兩個頭——迴歸頭預測「未來 N 個交易日的報酬率」，分類頭預測「報酬率會不會超過某個門檻」。傳統 ML 是兩個各自獨立訓練的模型共用同一份特徵矩陣；神經網路則是真正共用一個 encoder、分出兩個 head。

**選股分數**：把兩個輸出各自做**當日橫斷面 z-score** 之後加權平均（權重可調）。先前提供過「預期報酬 × 機率」的簡單版，但那會把虛高的機率直接乘進去放大，而機率恰好是這類模型最不可靠的部分，所以移除了。

**出場規則**四層依序判斷：最長持有天數 → 停損／停利 → 最少持有天數（沒過就連條件都不看）→ 規則條件（沿用既有的 KD／均線／連續漲跌條件引擎）。回測與正式上線呼叫同一份 `exit_rules.py`，避免兩邊悄悄分岔。

**每日排程**：每個交易日 15:00 對所有「已完成且未封存」的模型各跑一次——先判斷手上的要不要賣，再從當天全市場挑分數前 10 名買進。每次執行的耗時都會記錄。

### 可選的模型類型

| 類型 | 說明 |
|---|---|
| XGBoost / LightGBM / Random Forest | 樹模型。參數（樹數、深度、學習率、抽樣比例、葉節點最少樣本、`n_jobs`）都可調 |
| Logistic / Linear Regression | 線性模型。係數有正負號，看得出方向 |
| MLP / GRU / LSTM | PyTorch，**必須有 GPU**。層數、寬度、activation、dropout、learning rate、epochs、batch size、序列長度都可調，附早停與最佳權重還原 |

神經網路刻意設計成「設定要用 GPU 卻沒有 GPU 就直接讓訓練失敗」，不靜默退回 CPU——不然使用者會以為跑的是 GPU，實際上慢很多卻毫無察覺。

## 特徵工程

目前 **112 項**特徵，全部嚴格只用「該交易日收盤後就已經知道」的資料。避免 look-ahead 是這裡最關鍵的一環：只要有一個特徵偷看到未來，回測就會好看到不真實，但上線完全不能用。

| 來源 | 內容 |
|---|---|
| 價量 | K 棒形狀、4 個視窗（5/10/20/60）× 7 個滾動運算子、均線乖離、量比、連續漲跌。做法參考 Qlib 的 Alpha158 |
| 技術指標 | KD（與策略引擎共用同一份實作） |
| 估值 | 本益比、殖利率、股價淨值比。月頻快照，用 `merge_asof` 取「日期不晚於特徵日」的最後一筆 |
| 大盤 | 市場漲跌幅（1/5/20 日）、市場寬度、大盤均線乖離，以及個股相對大盤的強弱 |
| 籌碼 | 三大法人買賣超、融資餘額變化、外資持股比率與其 20 日增減（TWSE T86 / MI_MARGN / MI_QFIIS） |
| 股權分散 | 大戶／中實戶／散戶持股比例與 4 週變化（集保 TDCC，**週頻**） |
| 產業別 | 產業別 one-hot 欄位（TWSE 上市公司基本資料）。目前 1093 / 1382 檔有分類，其餘是 ETF 與受益證券 |

週頻的股權分散資料用 `allow_exact_matches=False` 做「日期**嚴格早於**特徵日」的接合——週五的快照要到週六才發布，用 `<=` 會在週五當天看到還沒公布的數字。

四組預設特徵集：**精選**（19 項，人工挑過、彼此重疊較少）／**精選＋產業別**（57 項）／**Alpha158 精簡版**（全部 112 項）／**純價量**（50 項，對照組）。

### 橫斷面處理

選股要回答的是「今天這 1300 檔裡哪幾檔相對強」，所以重點不是把數字弄準，而是讓同一天的股票可以公平比較。三個選項都是同一天的橫斷面運算，不看未來：

- **橫斷面排名**：把特徵換成當天在全市場的分位數。比 z-score 好的地方是不會拿去年的數值跟今年比。
- **超額報酬 label**：把個股報酬減掉同期間的大盤報酬，問「會不會贏過大盤」而不是「會不會漲」。
- **產業中性化**：減掉當天同產業的中位數。**實測有害，預設關閉**（見下）。

大盤特徵與產業 one-hot 一律跳過這些運算——它們在同一天對所有股票是同一個值或是 0/1 指示欄，排名會讓全市場拿到同一個名次、減中位數會讓整欄變成 0。

## 驗證方式

單次切分（train/validation/test 各一段）量到的往往是「那一段測試期剛好是什麼行情」。所以預設是**滾動驗證（walk-forward）**：把整段歷史切成好幾折，每折往後推移固定月數、各自訓練各自評分，最後看平均值與標準差。每折的標準化參數各自從自己的訓練段算，不共用。

**幾折全為正比平均值本身更值得看**——平均高但只有三折為正，代表某一折特別好而已。

## 目前的成效

最好的設定（LightGBM、預測未來 5 日、超額報酬、橫斷面排名、19 項精選特徵、六折滾動）：

```
測試 Rank IC  +0.0651 ± 0.0145   六折全為正
測試 AUC      0.5985
```

業界的多因子訊號長期穩定在 0.03~0.05 就算堪用，所以這個數字**不算無意義，但也遠遠稱不上能用**——同一套設定的回測平均報酬仍是負的（扣掉約 0.6% 的來回成本之後）。

幾個量過但**沒有用**的東西，一併記錄免得重複踩：

| 做法 | 結果 |
|---|---|
| 產業中性化 | +0.065 → **+0.039**，連訓練分數都一起掉，代表移除的是真訊號 |
| 產業 one-hot | +0.072，但標準差翻倍、六折只贏四折，配對 t=0.69，跟雜訊分不開 |
| 加入外資持股比率等籌碼存量 | 重要性排全模型第一，但訓練分數升、測試分數降——模型很愛、學不到會外推的東西 |
| 集保股權分散 | **無法評估**：滾動折次的訓練期都早於資料起點，特徵在訓練時 100% 是空的 |

## 技術架構

| 元件 | 技術 |
|---|---|
| 後端 | Python 3.12 + FastAPI + SQLAlchemy 2.0 + APScheduler |
| 機器學習 | scikit-learn、XGBoost、LightGBM、PyTorch 2.5（CUDA 12.4） |
| 資料處理 | NumPy + pandas（特徵管線全向量化） |
| 資料庫 | PostgreSQL 16 |
| 前端 | React + TypeScript + Vite |
| 圖表 | lightweight-charts ＋ 手刻 SVG（散佈圖與校準曲線的 X 軸不是時間） |
| 容器化 | Docker Compose |

訓練丟到 `ProcessPoolExecutor(max_workers=1)` 執行，所以**一次只跑一個模型**，同時送多個會排隊——這既避免阻塞 FastAPI 的 event loop，也避免兩個訓練一起搶記憶體。後端重啟時會把中斷的標成失敗、把還沒開始的重新排回佇列。

## 快速開始

### 需求

- Docker 與 Docker Compose
- **NVIDIA GPU + NVIDIA Container Toolkit**（只有訓練 MLP／GRU／LSTM 需要。沒有的話把 `docker-compose.yml` 裡 backend 的 `deploy.resources` 那段拿掉，樹模型與線性模型照常可用）

### 步驟

1. 複製環境變數範例檔：

   ```bash
   cp .env.example .env
   ```

   打開 `.env`，把 `POSTGRES_PASSWORD` 與 `TWSTOCK_JWT_SECRET` 改成隨機字串（`python -c "import secrets; print(secrets.token_urlsafe(32))"`）。**`TWSTOCK_JWT_SECRET` 沒有預設值，沒設定後端會直接啟動失敗。**另外把 `TWSTOCK_ADMIN_PASSWORD` 從預設的 `admin` 改掉。

2. 啟動：

   ```bash
   docker compose up -d --build
   ```

   第一次建置會拉 PyTorch 的 CUDA wheel，約 2.5GB。

3. 開啟：
   - 前端 http://localhost:5173
   - API 文件 http://localhost:8000/docs

4. 用 `.env` 裡的管理員帳密登入 → `/admin` 先把日K與籌碼面回補起來（**這步不能跳過**，沒有足夠歷史就訓練不出東西）→ `/admin/models` 送出第一次訓練。

### 環境變數（`.env`）

| 變數 | 說明 | 預設值 |
|---|---|---|
| `POSTGRES_PASSWORD` | PostgreSQL 密碼 | 需自行設定 |
| `TWSTOCK_JWT_SECRET` | JWT 簽章密鑰 | **必填，無預設值** |
| `TWSTOCK_ADMIN_USERNAME` / `TWSTOCK_ADMIN_PASSWORD` | 管理員帳密 | `admin` / `admin`（**請改掉**） |
| `TWSTOCK_CORS_ORIGIN_REGEX` | 要從別台裝置連進來才需要。預設只允許 localhost | 空 |

`.env.example` 裡還有 `TWSTOCK_INITIAL_CASH`、`TWSTOCK_POLL_INTERVAL_SECONDS`、`TWSTOCK_TRADING_START` / `TWSTOCK_TRADING_END` 等幾項，那些是舊的零股模擬器留下來的，對這個系統沒有作用。

從外網存取建議用 Tailscale 之類的方式，不要直接把埠開到公網——這個系統沒有為公開暴露做過任何加固。

  services/

## 已知限制

- **產業別沒有歷史。**TWSE 只提供現在的分類，早期樣本是用現況回推。產業別極少變動，這個近似可以接受，但要知道有這件事。
- **集保股權分散表只能往後累積。**TDCC 的開放資料端點只給最新一週，沒有歷史查詢。
- **樣本期間仍然偏短。**目前約兩年日K，六折滾動的折與折之間訓練期高度重疊，所以標準差不能直接當信賴區間用。
- **記憶體是瓶頸而不是 CPU。**特徵是 list of dict，一列 115 個 key 就要約 6KB，65 萬列約 3.7GB（同樣數字放 float64 矩陣只要 0.56GB）。調大 `n_jobs` 之前先確認還有餘裕。
- 舊的零股模擬交易功能（下單、撮合、自選股、排行榜、一般使用者帳號）已全部下線。程式碼與資料表保留在 repo 裡但不再對外開放，部分服務（手續費計算、技術指標、條件引擎）被新系統當內部零件重用。
